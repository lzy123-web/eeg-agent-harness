## 迭代 0：同载荷因果拆分

新增同载荷评价器。每个请求只调用一次模型，同一原始 `IntentSpec` 分别进入冻结 v0 校验器和候选 v1 编译器。由此，字段已经错误时归为基座模型提取错误；字段正确但决策错误时才归为 Harness 校验或规划错误。

开发集预登记抽取 8 例，`deepseek-flash` 实际返回模型标识同为 `deepseek-flash`：

- 8 次请求，14,628 tokens；
- 严格字段全对 3/8；
- v0 端到端决策正确 4/8，v1 为 7/8；
- 在严格字段全对的 3 例上，v0 为 1/3，v1 为 3/3；
- 两者均无 dangerous accept。

该结果是开发诊断，不是 holdout 成绩。

## 迭代 1：修正错误归因，而不是放宽方法

首版 scorer 只比较任务、目标和参数，却用请求中的规范禁止项替代模型输出进行评分，也没有检查语义概念 schema。它把 I14 错归为“Harness 误拒”。检查原始输出后发现：模型把合法概念 `quality_measurement` 写成不存在的 `epoch_quality`，并额外生成未请求的禁止项。这是基座输出契约错误，不是编译器应当接受的表达变体。

修订：

1. scorer 直接比较模型的 `forbidden_operations`；
2. 检查任务所需语义概念集合、精确引用和参数证据；
3. 同时报告端到端正确率与 `raw-correct` 条件下的校验正确率；
4. 保留 I14 原始失败，不通过放宽 schema 或新增提示词使其通过。

## 迭代 2：否定作用域的形态稳定性

I13 使用 `without quality-based removal`。原有规范化只识别紧邻的动词形态，无法稳定识别带修饰语的名词化禁止表达。候选方法的安全边界不能依赖模型是否恰好填写 `forbidden_operations`，因此把请求侧禁止项改为“否定触发词 + 有界修饰跨度 + 操作词形”的作用域规则。它仍只是安全规范化部件，不是独立论文贡献；核心机制仍是类型化 Claim–Evidence、Requirement Projection、先决条件闭包和高风险授权作用域。

## 当前判断

- 开发集支持“v0 固定短语锚点存在误拒，v1 可在不降低高风险授权约束的条件下恢复”的机制假设。
- 开发集也暴露了 DeepSeek 的 schema 遵循错误；Harness 不能把这类错误自动包装为合法意图。
- 样本量小且只有单人 gold 审核，不能据此宣称独立创新或统计优势。
- 下一步锁定实现和 evaluator，只打开预选 holdout 子集做 Flash/Pro 同条件对照。
