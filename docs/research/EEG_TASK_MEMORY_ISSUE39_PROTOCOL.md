# Issue #39：任务记忆真实使用价值配对协议（调用前冻结）

状态：2026-10-25 冻结开发/确认脚本与预算；本文件和 `config/point1_task_memory_issue39.json` 在首次本轮付费调用前提交。沿用 Draft PR #37、现有 HiAgent 启发的任务 episode / 摘要 / 检索 / 证据读取机制，不声称完整复现 HiAgent。旧 v1/v2/v3 结果与失败不改写。

## 研究问题及公平性

分开评价两项：①任务级记忆 H（或 HE）相对于不截断完整历史 F、常规摘要 S 的闭环使用与成本；② EEG 科学对象/版本分组 HE 相对于具备相同任务、时间、修订、记录检索及 `read_task` 权限的强通用 H 的增量。四臂都使用同一合成 EEG 生成器、真实 Registry/Executor、模型、能力目录、动作 schema、证据读取与最终回答入口。每臂仅见自身执行所得历史，不能看到离线 target key、期望动作或 oracle。F 不人为截断、重复注入原始结果，也不刻意塞无关历史。`switch_analyze` 和带 record 的 `analyze` 均可合法完成跨记录计算；单纯 `switch` 不能算作分析完成。科学读取的记录/通道/窗口/事件/版本校验为公共规则，不能对某臂放宽。

## 数据与运行顺序

开发初评固定为已有 v2 协议 `N-medium`（旧脚本，已见开发集）：6 个有意义的连续/事件分析任务与 3 个历史追问，逐臂 F→S→H→HE，各历史追问额外请求最终自然语言回答。开发修订只可用该开发集，最多两轮；同一脚本重复不计作独立确认。确认集在本轮调用前单独冻结为 `C-short`（2 个连续任务 + 1 个历史回答）及 `C-long`（6 个连续/事件任务、两个参数版本修订 + 2 个历史回答）。确认严格 F→S→H→HE，不能依据确认输出再次调方法或真值。若确认揭示公共评测器 bug，仅按预先明确的语义修复并保留首次结果，不能重写合成数据或科学真值。确认集 `C-long` 的事件功率窗口最低 1 s、SYNTH-C1 追问与当前工具契约均已在调用前经真实工具预检；试次数和频带值由独立 NumPy/SciPy oracle 及真实工具双重核查。

## 预算和账本

本 Issue 新阶段最多 **160 次 external completion / 300,000 API tokens**，不继承旧暂停预算。预留 smoke≤8、初评≤48、开发修订≤32、确认≤56、机动≤16；机动不作为消耗目标。所有外部尝试（含失败）在网络请求前进入同一被 Git 忽略的 `artifacts/point1_task_memory/issue39/budget.jsonl`，跨进程累计锁定；成功按服务 usage 记账，未知/中断按输入 UTF-8 字节上界 + 输出上限保守占用，不能删除账本重置预算。禁用内部网络重试，每次调用输出上限≤1000 tokens。记录 requested/reported model、逐臂实际 completion、prompt/completion/total tokens、时延、结果和错误；不因模型成本导致未完成某臂却计算其成功率。

独立运行命令（仅明确授权后的 opt-in）：`PYTHONPATH=src python -m eeg_harness.research.task_memory_issue39 --phase smoke|initial|revision|confirmation --enable-paid-issue39`。`--ledger-status` 只读，不需要密钥。API 地址、模型、密钥从已有 `EEG_HARNESS_LLM_*` 环境变量读入，不写入仓库；本协议不传 temperature，服务端默认值属于复现限制。原始 assistant 消息和逐轮 JSON 只保存于 Git 忽略的本地 artifacts，公开仅脱敏聚合/失败摘要。只发送合成 EEG 的必要元信息、工具目录、请求与合成结果，不发送真实受试者 EEG、事件、特征、权重或密钥。

## 分层评价与停线

每轮分开记录：动作类型/参数/版本是否对齐；工具实际完成及错误；历史候选是否进入上下文；模型是否读取正确记录、范围、版本和真实结果；最终回答是否忠实于数值、单位和条件；调用次数、输入/输出 token、额外工作卡字数、时延及冗余证据读取。历史命中不能代替最终答案。数值核对先比较工具结果与独立数组 oracle（浮点容差 2%，试次数精确），再核对文字回答；因窗口数字和结果数字可能同为整数，机械文本包含检查只能辅助，含混回答作人工逐例判定并公开理由。至少列出首轮失败，不把开发/确认混报。

失败归因固定为：公共动作误选、参数/分析契约、摘要遗漏或上下文选择、模型读取/证据校验误拒、最终回答歪曲、服务故障和不必要重复读取。若 F/S/H/HE 同失误，先怀疑公共入口而非 EEG 记忆收益；若 HE/H 等效且更贵，应停止扩充 EEG 专用排序/绑定或简化之。最多两轮有机制依据的开发修订；不为提高确认成绩追加词表特例。不要求 HE 胜出。结论分别给出成熟任务记忆、公共工程能力与 EEG 对象/版本适配的证据等级。

## 预检纠正记录（均在首次本轮付费调用前）

- `C-long` 的事件功率修订窗口初稿 0–0.5 s 与原工具最短窗契约冲突，改为 0–1.5 s；试次数修订仍 0–0.5 s。属于冻结前科学可执行性修正。
- 事件功率追问选 SYNTH-C1 而非可能接近零的另一合成通道，以便独立数值和最终文字核对。
- 公共动作增加 switch+analyze 原子操作语义；公共证据读取接受事件功率结果中真实存在的通道。两项均对 F/S/H/HE 同样适用，先于真实初评冻结。

## 开发后、首次独立确认前的版本化修订（保留上文原协议）

第一轮及一次开发复验合计已用 78 completion / 200,350 tokens。按已观察的逐调用成本，原定短/长集各四臂 56 completion 可能越过剩余 99,650-token 硬上限。此修订仅根据**开发成本**进行，尚未读取确认模型输出；合成确认请求、任务真值、科学 oracle、四臂定义与总预算均不变。

方法修订 2 将 H/HE 工作卡从完整工具结果改为任务摘要（含记录、能力、参数/版本、真实来源、结果顶层字段及读取 ID）；精确数值通过公共 `read_task` 恢复。此为 HiAgent 启发的任务级压缩落实，不影响 F/S 原上下文，也不改变公共科学读取校验。它也可能因缺少直接结果而伤害模型，必须由确认记录检验，不预设收益。

为保证硬预算下优先形成至少一组长历史 H/HE 配对，确认执行顺序修订为：`C-short` 仍 F→S→H→HE；`C-long` 改 H→HE→F→S。顺序非随机、属于预算驱动的协议偏离，故不把不同服务时刻的微小差异当因果效应；如果预算在某臂前停止，未执行臂标为缺失，不用已有臂外推四臂成功率。初评的旧协议 SHA 与修订后的确认协议 SHA 均随各自原始日志保存，不能将确认集再用于方法调节。
