## 开发修订 1：父任务记录绑定

`live_turn` 中 `revise` 未给 record 时显式从真实 `parent_task_id` 对应的已完成任务继承 record；对缺失/不合法父任务不降级成新分析。配对评分使用实际完成记录而非要求模型重复显式给 record。新增 Fake 回归：切到 B 后修订 A 的父任务仍在 A 上生成新版本。定向 17/17 通过。保留第一轮原始日志，不将重评分当成首次成绩。

| 根因卡 | 具体观察/定位 | 改动和可证伪预期 | 验证边界 |
|---|---|---|---|
| 公共修订记录绑定 | 开发 S/H 第 6 轮有效父 ID 指向 A，动作未重复 `record`；`live_turn` 默认当前 B，`MultiTurnEEGSession.analyze` 拒绝父记录不符 | 只在 parent 已存在且 action 未给 record 时从 parent 绑定；同一执行与评分应正确，显式冲突仍拒绝 | Fake 可以确定性证明接口修复；真实重跑可能有模型采样差异，不能只看分数归因 |
| 任务摘要未真正压缩 | 旧 H/HE 的 `completed_index` 虽摘要，`working_tasks` 仍为完整 `result_preview`；开发完整 token 与 F/S 接近，HE 另有分组冗余 | 工作集只给真实任务摘要/结果字段目录/读取 ID；同历史查询 ID 可见与数值读回不变，输入字符应下降 | 若真实模型因缺直接数值而读错/多次查证，或总 API token 不降，则压缩的净效益不成立 |

## 开发修订 1 复验（N-medium，同一开发脚本，不是独立确认）

H 9/9、12 completion / 33,410 tokens；HE 5/9、12 completion / 33,886 tokens。H 在父任务记录绑定修复后本次完成全部动作与历史读取，但单次配对不构成因果改进证明（与首轮模型采样差异未隔离）。HE 的 4 个错误中，3 个是把试次数请求选成 `epoch_quality`（含其修订），最后一个历史问题因正确试次数任务从未执行而无目标；其中**首轮尚无历史时已经选错**，不能归因于 EEG 对象组或检索。旧首轮第 2/8 错误与本轮新失败同时保留；没有证据支持针对 HE 增加特殊规则。真实预算到此为 78 completion / 200,350 tokens。因每次提示词中能力目录和完整 EEG 结果字段反复发送，平均调用约 2.5k tokens，确认集 56 次若按原样执行预计可能超过剩余 99,650 tokens；必须先做可核验的共同成本收缩或在硬上限内如实停止，不得偷偷提高预算。

## 开发修订 2：任务摘要压缩与确认调度

先前 H/HE 虽有 `completed_index`，`working_tasks` 仍携带整份真实工具 `result_preview`，使任务抽象没有真正降低读入成本。修订后工作卡仅含任务摘要和原请求，`result_fields` 缩为顶层字段目录；源/记录/能力/参数/版本与 `read_task_id` 保留，真实结果、科学条件和数值仍由公共读口返回。离线预检中 `C-long` 6 项历史后的工作上下文：F 6,432 字符、S 5,802、H 4,024、HE 4,762；HE 额外对象版本组仍比 H 多 738 字符。压缩的实际 API token/正确性由确认集判断，不能用离线字符预测当成成功。

开发成本提示原 56 次确认可能超过剩余 token 硬上限。因此在**首次确认调用前**版本化修订顺序：短集四臂不变，长集优先 H→HE→F→S。脚本、真值、科学条件不变；若触顶则明确缺失，不补买额度、不再改方法。详情和顺序偏离风险见协议增补。

## 独立确认与最终判断

确认集在真实模型首次看到前冻结；开发后的**预算驱动顺序修订**见协议，未改请求/真值。外部请求名 `deepseek-chat`、本阶段 126 个有效响应报告名均为 `deepseek-flash`；`thinking=disabled`、每次输出上限 1000、内部重试 0、未显式发送 temperature。确认新增 48 completion / 92,182 tokens；总账 **126 completion / 292,532 API tokens**，无未知/中断占用、未越 160/300,000 硬上限。剩余 7,468 tokens 不足以安全完成 S 长历史剩余轮次及最终回答，因此账本在其第 3 轮请求前拦截。该行是**预算截断**，绝不是模型/摘要失误；S 长历史没有有效完整配对，不计算 2/8 之类误导性率，也不补跑或将残余额度花在非预注册小例上。

具体失败与责任层：

1. H 第 5 轮模型选 `revise`、正确父任务 ID 和新窗口，却漏了 `capability`，公共工具安全返回 `UNKNOWN_RECORD_OR_GOAL`；它是**动作参数契约**问题，不是旧任务未检索。第 8 轮因新版功率从未创建而要求澄清，没有编造 alpha 数值。第 7 轮旧 B 试次数读取正确并回答 **2**。
2. HE 第 1 轮尚无任何历史，已把“有效试次数”选成 `epoch_quality` 而非 `epoch_summary`；第 6 轮在错误目标上继续合法修订，第 7 轮虽读到了自己的旧质量结果，但不是用户要求的试次数任务。这是**科学目标/能力选择**及级联，不是检索 miss，也不能把回答中的“质量可用 2”当正确试次数证据。第 5/8 轮另一路 A tone 功率版本确实正确，最终 alpha 为 **3.2799997787269497×10⁻¹⁰ V²**，与独立 SciPy oracle 一致；不能以此遮盖另一目标错误。
3. F 第 3 轮给出目录中不存在的 `epoch_bandpower`（合法能力是 `event_bandpower`），公共执行拒绝。第 5/8 轮因缺 A tone 功率父版本而澄清，属于先前动作错误的安全级联，不是完整历史被截断。第 7 轮旧 B 试次数回答 **2**，正确。
4. S 的第 3 轮未发出请求：跨进程 token 预算检查拒绝，无 LLM 响应；此前两轮均正确。不能评价其长历史摘要能力。

最终文字逐条核对：确认中共 10 条自然语言历史答复（短集四臂各一、长集 H/HE/F 各二），短集四条的记录/窗/通道/RMS 与真实证据一致；长集 H/F 对旧 B 试次数的两条一致，二者对缺失新版 A 功率的两条都明确不产生数值（其中 H 的澄清提了科学上不等价的连续 PSD 备选，但未执行）；HE 对新 A 功率的数值/事件窗/频带/单位一致，而对旧 B 的一条来自错误的 `epoch_quality` 链，**科学任务不一致**。即 9 条可按已执行证据/安全澄清解释、1 条科学目标错位；这不是自动开放文本语义评分，人工核查只覆盖本阶段这 10 条。独立数值 oracle：短集 RMS `1.4142135677367759e-05 V`，长集旧 B count `2`，新 A tone/C1 alpha `3.2799997787269497e-10 V²`；工具结果容差 `rtol=5e-3, atol=5e-13` 或整数精确，参见定向测试。

### 成本、优化证据与结论边界

开发优化 1 的父任务记录绑定由 Fake 和实际修订路径验证了**公共接口正确性**；H 同脚本复验从 7/9 到 9/9，但模型采样、第一次错误链与完成任务数量同时变化，不能把 +2 因果归给此改动。HE 反而从 7/9 到 5/9，首轮无历史已选错质量能力；不存在可称为 HE 改善的证据。

优化 2 的压缩在**同一工具历史**离线比较：旧 H/HE 的 10 个追问 top-1 均 10/10，摘要版仍 10/10；工作上下文累计字符 H `65,428→47,722`（−27.1%）、HE `69,081→50,801`（−26.5%）。但真实闭环历史因各臂首轮动作分叉而不相同：长集 H 21,597 tokens、HE 23,944、F 21,409，不能把离线压缩等同于完整 API 节省。HE 相对 H 多科学对象组和 EEG 排序，在开发/确认均未显示稳定正确性增量；确认长集还更贵且少对一项。S 长集截断使整套方法相对合理摘要的较长任务价值**未完成验证**。本阶段没有公平重复随机种子/服务随机性控制或真实用户/数据外推，不报告显著性或泛化成功率。

**阶段判断**：任务 episode＋不可变证据＋按需读取是可运行的多轮 EEG Harness 能力，具体实用价值主要在可追溯旧版本和安全不编造；这些能力由所有臂共用，不能记为 HE 独占贡献。HiAgent 启发的 H 摘要/检索在同历史下节省上下文，但真实闭环尚未证明相对强 F/S 在正确性相同条件下降低总 token；额外 EEG 对象/版本 HE 的增量**当前无支持证据，建议先不扩充、可简化**。本研究问题不因此被一次负结果否定，但不应把 HE 包装成已成立的论文创新。

**下一阶段唯一优先事项**：在新授权预算下，冻结更省调用但仍含自然长历史的四臂**相同历史读取＋最终回答**配对（保留 F/S/H/HE、公平科学校验和独立 oracle），优先隔离“模型能力选择”与“上下文组织”并补齐本轮缺失的 S 长历史；当前预算不自动续用。若 H 仍与 F/S 持平且 HE 更贵，收敛为 H＋共享 EEG 来源/版本安全工程，不再增加 EEG 分组规则。
