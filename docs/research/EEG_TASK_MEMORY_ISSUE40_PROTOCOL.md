# Issue #40：任务记忆效用归因预冻结协议

状态：2026-10-25，付费调用前冻结。本协议承接 Issue #39 原始结果与 PR #37 审查评论，不覆盖旧实验。

## 问题与比较

单独比较两层：① H 任务级工作记忆对 F 完整历史、S 普通确定性摘要的正确性—总成本；② HE 额外 EEG 对象/版本分组对 H 的增量。四臂均访问同一份真实 Registry/Executor 在合成 EEG 上生成的不可变历史与同一 `read_task`；没有候选专属科学证据。实验层只评价历史证据定位与最终回答，不将首轮能力误选、任务未成功写入算作检索错误。

F 可从上下文直接回答，无需强制读工具；S、H、HE 也有同样选择。统一结构化动作 `answer(task_id, answer)`、`read(task_id)`、`clarify(question)`；若读取，最多一次相同规则的第二次 completion 生成自然语言答复。目标 ID、数值、oracle 不进入模型提示。每一查询从历史快照独立重置，四臂的 task/artifact ID 不变。所有输出仅限合成数据；原始响应存于 Git 忽略目录。

## 样本、阶段和预算

使用既有 `point1_task_memory_protocol_v2.json` 的 N-short/medium/long 真实工具历史，6 个自然问题，按 `config/point1_task_memory_issue40.json` 冻结。开发：三条历史各第一问；确认：三条历史各第二问。N-long 的旧/新版本以及 N-medium 的记录/事件条件可检验混淆；短链是不需摘要的参考。既有问题材料均属开发性、非盲法未见测试，确认只是本阶段未用来调方法的保留单元。分母是查询，不是独立受试者或独立长会话。

每个四臂查询单元最多 8 completions，前置准入预留 8 次和 24,000 tokens；额度不够则整单元不启动。开发结果分析后至多一次机制简化/修订；确认单元不用于调参。预留至少 24 次 / 60,000 tokens 给确认，至少 12 次 / 30,000 tokens 给有限闭环；阶段硬上限 96 次 / 240,000 tokens。CLI 以独立追加账本跨运行计费，尝试前先记 reservation，关闭自动重试。旧 Issue #39 账本绝不叠加。额度不是消耗目标。

短闭环固定为 N-short 的 3 次自然分析请求与 1 次最终历史回答；候选 H 与最强通用对照 F 各从首轮开始运行。闭环结果与同历史条件比较分别报告。若模型服务、预算或科学安全受阻，如实标未验证。

## 评分与归因

执行后独立 oracle 从合成原数组重算目标标量（PSD、RMS、有效试次数），校验 `task_id`、记录、能力/科学范围、参数、版本、来源、单位与结果。最终答复逐例审阅是否引用正确证据、数值/量级/单位与科学条件，明确把“模型选错卡”“读取后答错”“同值但错目标”“需要澄清”分开。成本报告实际 provider 总 token、completion 数、延迟和上下文大小，不只报告字符代理。统计不宣称显著性或外部泛化。HE 如无可归因收益，只收敛为 H；共有的证据守卫和版本约束不是 HE 的独占贡献。

## 执行后追加说明（不回写预冻结定义）

主配对的 6 个四臂单元按上述名单全部执行，开发/确认边界、查询与 oracle 均未修改。首次短闭环使用旧公共 `history` 动作，F 即使已持有完整数值也被强制读取；该成本接口不符合本协议直接回答机会相同的原则。保留首次 `closed` 原始结果，新增独立 `closed-direct` 运行：分析三轮仍用原公共动作和真实 Executor，最后历史追问改用本协议共同的 `answer/read/clarify` 接口。两次闭环均标已见开发性复核，不能把后一次冒充未见确认。
