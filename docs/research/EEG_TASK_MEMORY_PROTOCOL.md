# Issue #36 多轮 EEG 任务上下文实验协议 v1（预运行冻结）

本文件与机器可读 `config/point1_task_memory_protocol_v1.json` 在任何真实 LLM 输出及候选检索实现前冻结。原始 CIEDG、PR #27/#35、旧负结果均不改。6 条独立合成会话：开发 M1–M4、验证 M5–M6，每条 5–6 轮，包含连续/事件分析、记录切换、参数修订、历史追问及歧义。用户文本和结构化脚本由研究者受控预写，不是自然用户/专家标注。脚本中的期望任务引用和数值 oracle **仅评分器可见**；记忆写入必须依据实际执行而非脚本 gold。

合成记录 A/B 都为 8 s、128 Hz、两通道 `SYNTH-C1/C2`；A 与 B 的通道幅值和后半段增益不同，使不同记录、窗口、条件的真实输出可区分。事件表 A：stimulus=1/3/5 s、control=2/4 s；B：stimulus=1.5/4.5 s、control=2.5/5.5 s。所有执行通过同一真实 Registry/Executor/v3 `run_instances`，历史值从真实证据读取；幅值由 NumPy、PSD/事件功率由 SciPy 独立重算（相对 5e-3、绝对 5e-13）。模型任务不是必需，绝不向外部服务发送真实 EDF、受试者信息或真实特征。

**共同操作**：`analyze(record, goal)`、`revise(parent_task, goal)`（生成新任务，不覆盖旧证据）、`switch(record)`、`history(task_id)`、`clarify`。每轮真实 LLM 只获得当轮自然语言、当前记录别名、能力描述、策略选出的历史卡片与同一只读 `read_task` 接口；它不直接见脚本的期望 target ID。无历史的首次分析也走共同接口，不能拿旧 v3 的 `run()` 重置行为作弱基线。所有方案允许同样的澄清和原工具错误结构。

**实验 1：相同历史前缀回放。** 先按冻结脚本在合成记录上真正运行工具，生成同一原始历史；F/S/G/E/E−scope 分别为查询点选择上下文，记录目标覆盖、误取、多解澄清、工作上下文字符/估计 token。此项隔离选择/读取，不冒充真实自主多轮交互。F 不截断；S 摘要保存正常对象/数值入口；G 可用所有共享结构化字段和通用 record/time 检索；E 只改变科学对象/版本排序。工作上下文预算设为最近 3 个完整 task card + 一个常规摘要量级，**不以极小预算压制对照**；F 成本/正确性独立报告。

**实验 2：真实闭环。** 至少两条短完整脚本，G/E 成对运行，均同一 DeepSeek 模型、温度/输出上限、User 文本、工具/执行校验/回答协议；单轮无法解决时可 `clarify`，后续脚本不得用另一臂历史修补。完整记录初次响应、LLM 选择、检索、工具调用、答案、状态与成本。若预算够可加 F/S 配对，但先保留 G/E 配额。候选没有任何专享 gold、任务 ID 或正确答案提示。

**主指标**：每个追问所需真实 task 的 top-k 命中/错取；记录/通道/窗口/事件 scope/配置/版本准确；可执行后续分析完成率、正确澄清与过度澄清；从真实结果读取的数值与单位忠实；重复 EEG 计算；上下文字符和 API tokens（含摘要/检索请求）；耗时。归因分历史写入、检索、模型读取误用、公共解析/引文接口、Executor/资源。比较按会话呈现，不做小样本显著性宣称。F 完整历史不因较长被算错误；G/E 共享同一检索机会与原始条目。

外部服务总硬上限 **96 completions / 300,000 tokens**（含摘要/检索改写/重试）；优先仅 G/E 两条短闭环，预留对称预算，最多必要的开发修订 2 次，不将额度当消耗目标。每个响应到达即本地 append-only 保存到被 Git 忽略的 `artifacts/`，公开文档只提交合成安全的脱敏逐例摘要。验证会话首次运行后不可按结果改脚本、gold、候选或基线；评分器 bug 须保留首次评分并追加审计。若 G/E 持平，直接承认适配收益未证。
