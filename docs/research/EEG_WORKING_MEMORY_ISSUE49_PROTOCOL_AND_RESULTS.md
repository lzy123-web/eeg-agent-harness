## 2. 最小充分方案与继承取舍

只补“不要重算、记得回答”提示，无法保证begin/amend的科学范围一致，也不能区分同一有效结果和内容相似的另一工件。另建完整需求DSL或独立规划/裁判模型则增加范围与付费决策，并不能自动证明用户意图完整。选用现有科学子目标、真实档案和原循环上的三个共同机制：

1. **同一合同校验入口**：创建、补充未知项、技术纠正均检查允许字段/类型/变换边界/来源；已确认科学选择改变必须新版本。拒绝不部分修改合同或执行未经授权的变换。原工具schema支持某参数，不代表当前工作记忆模式已经授权它。
2. **请求—交付进度与有效结果复用**：模型用实际用户引文提出需求及覆盖关系，程序核对可表示的引用、对象和真实结果；等价计算依记录/参数/配置/版本/工件有效绑定复用，不因换标题或delivery key重算。明确重算、新范围、失效和新配置仍允许执行。原请求持续可见，模型清单不是离线gold，遗漏仍算未完成。
3. **完整交付的工作视图与资源收尾**：保留归档后完成反馈、必要精确值和未决项，原轨迹外存可恢复。必要时公共预算策略把工具集合收束到finish_task，让真实模型用已见证据回答完整、部分或澄清；程序不合成科学答案。

这三项适用于working、强summary和full。共同可靠性修复不能算候选独有优势。HiAgent继承是任务组织、当前工作视图、归档与按需恢复；本版实际是结构化进度＋最近原生批次＋必要精确证据，而非“全部当前行动观察直到完成都驻留”。需要足够完成反馈，但不机械重发完整已解决轨迹。

主要代价：科学来源/合同/覆盖字段增加接口及输入成本；来源逐字引用并非任意语言理解证明；保守完整输入预留可能让模型提前部分交付；已完成等价复用必须避免误挡用户合法重算。以上均须以反例及真实日志检查，不以新增测试数代替方法收益。

### 9.1 逐类失败根因，不混为“记忆检索失败”

- **模型来源登记与自纠**：开发首次把引文写成省略号后被拒，自行纠正。C把已指定target的证据引文写错而额外请求用户确认；曾声明−0.5～1秒但未执行，最终“没有代为假设”不精确。A新窗最初以“同一通道”自证通道来源，随后amend用旧真实结果来源成功。
- **任务级未决连带阻断独立输出**：B的`theta_c2_target.labels`引文只写“该条件…”未包括target，未通过来源验证；同一goal的任何issue使已合法的连续amplitude/psd也无法执行。随后模型将可技术修正的登记问题转为用户确认，不能归为用户本来缺参数。冻结后不放松来源真值、不按此例补关键词。
- **资源与阶段边界**：可靠最坏最终输入预留导致开发次轮、A历史追问、B的后续展开提前收尾。总API tokens尚未到上限；这是预算分配/容量接纳限制，不是外部API不可用。A被拒一次后使用新recovery成功交付未决说明，证明修订可行动；它没有完成精确查询。
- **B部分交付的公共误拒**：第二轮模型引用第一轮真实逐字原文解释欠账，但旧pending目的未被touch/restore，`RequestProgress.valid_quote`只接受当前或related目的所在轮，故旧引文被拒三次。原文确实存在于历史，这不是虚构引文。请求相关性与证据数值可见性是两个不同检查；本次修订只解决后者，未解决前者。确认后保留失败而不替换成绩。
- **读取及服务遵约**：B首次请求5个字段，超过公共1～4字段界而被拒；后续仅finish schema、强制finish的真实响应仍提出read_evidence，被FINAL_DELIVERY_ONLY安全拒绝。后者是实际服务动作遵约问题，不能把被拒读取视为成功读回。
- **最终科学表达**：C原V²正确但额外单位换算错误、质量阈值措辞过宽；B首轮又将“RMS与alpha绝对功率”共同标成V²，RMS应为V；当前程序核查引用与真实结果，不独立证明每句自然语言表达正确。本轮没有新增回答裁判Agent，也没有用数值oracle掩盖该错误。

B第二轮按预定协议发送，但由于首轮失败，不存在其“刚才原试次”的实际前提。因此它验证的是缺失前提时的安全续接，**没有产生评估成功原过程恢复的条件**。不能把这段会话的失败全部计为记忆恢复失败，更不能报告已验证该机制。
