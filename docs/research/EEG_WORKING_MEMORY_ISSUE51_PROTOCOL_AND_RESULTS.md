## 边界与协议

目标是把完整请求的对象归属、结果实例完成、活动 AO、摘要、精确读回与过程恢复接在原 Agent/Executor 上。不是重选题、第三种规划器、临床系统，也不是未见任务准确率实验。开发自然语句和确认结构相同、合成数值不同，不能称独立语言泛化成绩。

完整配置：`config/point1_working_memory_issue51.json`。新的独立总量 72 completion/650,000 API tokens，开发最多 18/150,000、冻结自主确认最多 36/500,000；确认完成且审核后才允许可选完整三臂配对，最多18/300,000（每臂6/100,000），**后者只能使用本阶段实际剩余，总量始终不超过72/650,000**。这是优先级预约及各阶段上限，不是将三个token上限相加授权。实际 tokens 按服务返回 usage 计入；未返回 usage 按保守预约计入预算，所有尝试与失败留痕。默认自动重试 0。预算不是消耗目标。

先真实工具离线门槛与完整单元资源预检；确认保留独立份额。最多两次有明确根因的开发架构修订，确认冻结后每类一次、不得按成绩改方法/科学要求或择优保留。有限诊断失败时应停止联网定位；合成数据和必要结果可出站，真实 EEG 不参与。

自主会话从多记录连续信号基本分析与事件分析缺窗开始，随后补充事件窗、修订连续范围并比较，再基于原事件工件追加质量及回顾旧结果。驱动只发送自然语言和合成元信息，不传工具名、正确任务 ID、调用顺序或预期数值。focus、restore、read 是否发生，从原生模型输出及下一输入核对，不能事后贴标签。未必要恢复时直接用摘要合法。

可选同历史 full/summary/working 使用同一真实工具历史和读取权限，完整配对入场；摘要有实际精确字段。三臂共享科学任务档案，差异只能归为呈现与读取粒度，不证明任务组织本身的独立贡献。没有足够完整配对资源就整单元不运行。

## 离线门槛

- 原 Executor 的 A/B 裁剪来源反例及合法多对象范围；事件相对窗与连续窗不能混用。
- 两份同工具不同窗口结果、多工具/多记录实例、缺参项与合法工作并存、正确 ready/归档/暂挂。
- 真实版本与工件身份、合法复用、过程恢复后原工件追加质量，精确字段读回进入下一模型输入。
- 已见+新读 union、实际数值差值/比值与单位契约、非法比较拒绝；所有模式共享约束；旧模式回归保留。
- 独立新追加账本、真实 wire 与输出预约、完整活动/归档/读回/恢复/最终视图预检，不用经验 tokens 比例放宽预算。

### 开发首次失败与修订1

初版代码/协议`4b0e675`的dev-initial仅运行原自然首轮，真实3次/25,544tokens（输入24,205/输出1,339）。模型主动提出了有意义的多结果科学目的，但将报告频带、事件报告通道、无处理声明和未知null窗口混入scope。宽泛JSON对象schema与内部严格计算字段不一致，导致整项focus被拒；随后三项连续指标和事件元信息仍真实执行。这是公共契约的科学角色混淆，不能统称模型意图理解错，也不能将自动fallback多结果档案当自主科学子目标成功。

最终原V²数值正确，但将`2.00e-10 V²`换算为`0.200 µV²`，正确为`200 µV²`。独立审计确认当时三次实际输入都没有scaled_display；仅系统文字建议用canonical不等于已提供正确缩放依据。原回答及失败完整保留。

### 根因分层，而不是笼统说模型没理解

1. **辅助只读动作误拒**：第二轮模型明确选择record=A，但为list_events使用当前补窗片段；`scientific_request_binding._fallback_records/resolve_action_source`（111/191行）按多记录历史处理空scope元信息查询，返回AMBIGUOUS_RECORD_SOURCE。模型随后仍正确执行连续修订和事件科学动作。元信息读取与需要科学范围授权的计算尚未完全区分。
2. **直接完成阻断**：`ScientificTaskStore.completion_check`第250行对所有pending_actions作一票否决；该list_events不是模型声明的三项必需结果，失败却变成永久未决科学义务，导致`UNFINISHED_DECLARED_TASK`。这是本方法当前生命周期缺陷，不是所需数值未得到。
3. **状态展示不一致**：原`WorkingMemoryStore.execute_numeric`第225行在数值成功后清空unresolved，但另一个pending列表仍非空。后续输入出现“所有实例满足、unresolved=[]”同时ready=false；模型重复completed三次没有有效恢复。不能将这种矛盾全归责给模型。
4. **自然续接身份尚未收束**：新标题建了s2而非续接s1；`focus_task`以标题和默认记录匹配，`_bind_requirement`只更新当前目的。旧s1仍写事件缺窗，虽然真实事件已在s2完成。它不是这次finish拒绝的直接条件，却暴露目的身份与自然语义续接的结构边界；两个suspended不等于两项数值科学失败。
5. **已发生的局部恢复**：event_bandpower引用旧轮原文被当前request_span规则拒绝，模型换为合法当前来源后成功；全部失败保留。没有修改科学真值替模型通过。

确认后只读定位，不修改候选，也不因尚有预算继续刷同一任务。下一阶段若允许修正，应将本次失败当已见回归，不能再作为独立确认成绩。

### 记忆到底用了什么

- 真实模型自主focus已接纳，两个自然目的分别包含多项实际结果；活动AO在后续实际决策前可见，未发生“首个PSD就完整归档”的旧缺陷。
- 首轮暂挂卡进入第二轮真实输入；旧PSD `t2`被模型选为compare_results的真实左操作数，新` t4`保留版本关系。因此**摘要中旧结果用于后续科学比较**已有直接调用证据。它不是因果收益证明。
- 所有新语义目的最终仍suspended，没有一条完整自主“完成归档→过程恢复→新分析”的通过记录。`read_result=0`、`restore_task=0`；不强迫额外读取，不把直接可见旧值冒充过程恢复。
- 精确读回、恢复原行动观察后原Epoch追加质量、已有证据与新读回union有原工具/Fake机制验证；真实自主第三轮未到达，只能标未验证。
- F/S/working的公平共同接口与同历史离线预检存在；第二层真实比较**因第一层科学准入失败而未运行，并非本次预算已不足**。没有成本/正确率胜出结论。
