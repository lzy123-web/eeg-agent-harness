# 多任务共同执行方法的后续公平评价预案（Issue #26）

本文件不是本轮正式比较结果。旧 Issue #16/PR #23 数据、gold 和负结果保持原样；本轮开发请求/故障反例已见，不得当未来 holdout。正式实验应先冻结任务、数据生成种子、合法性 oracle、预算、版本、人工审查规则和失败分类，然后独立建立未见集。

## 比较对象与回答的问题

| 对照 | 应回答的问题 | 公平条件 |
|---|---|---|
| 原生 tool-calling Agent | 图方法是否降低非法调用、遗漏约束或无证据回答？ | 同一 LLM/温度/工具定义、同请求与 token/调用预算；不把原生 Agent 故意限成无状态单步 |
| 冻结旧 v1.1 CIEDG | 新方法相对 event-only 覆盖了什么科学对象与状态？ | 旧运行路径不回改；对不支持任务记 `not_applicable` 而非当普通失败刷优势 |
| 强动态 Expert | 共同图是否带来独立的跨任务维护/恢复价值？ | Expert 同样获得 Profile、ToolSpec、质量证据、合法操作、状态变化与同预算；允许最佳合理手工模块化，不用弱固定 DAG 冒充 |
| 新方法消融 | record/model 版本绑定、跨族目标依赖、类型/来源门、证据发布各贡献多少？ | 只移除被检验机制，保持其余提示、工具、资源和预算一致；失效案例不得在消融配置里被静默删除 |
| 本地实际数据应用 | 方法链与原确定性流程在同输入下数值、事件计数、来源是否一致？ | 数据/派生结果不外发；R3 标签未知处只比可确认的数字条件；模型另用合法原资源 |

## 有限场景与分层终点

建议各任务族至少含：合法单目标与双目标、缺参、错通道/采样率/Profile、缺资源、事件缺失/边界、明确禁止变换、工具瞬态失败、记录或 Epoch 状态变更、输出类型/来源不一致、回答数值或条件歪曲。三族按科学对象而非工具个数分别统计。开发集可用于诊断；未见集的科学要求和评分器不得按结果调节。

指标分层报告：

1. 意图：用户显式科学目标、参数、否定授权是否完整且无幻增；旧 parser 对多正向目标与事件 quote 的缺陷单列。
2. 编译：合法目标覆盖、Profile/资源/数据类型拒绝、是否错误地执行子集。
3. 执行状态：依赖满足、变换后只使用当前有效 artifact、局部重跑/内容等价复用正确性、工具数与耗时。
4. 数学与来源：独立 PSD/Epoch/model shape oracle、本地确定性流程比对、provenance 与原记录哈希。
5. 答案：必需工具结果被引用、数值/科学条件没有被篡改、错误时不发布部分结果。
6. 工程/研究代价：新增科学任务族的契约/适配/测试变更面、专家流程分支与维护成本；代码行数只是辅助，不能单独判创新。

失败逐例归因于语言解析、目标/契约表达、科学适用性、状态/依赖、工具数学、恢复、答案证据或资源缺失。合成输入仅证明工程与受控科学不变量；真实 R3/EDF 不能证明跨儿童样本泛化或 ASD 辅助评估效能。若强 Expert 同样正确而新方法没有可量化的维护/可迁移优势，应保留持平或 No-Go 判断；本轮不提前下结论。
