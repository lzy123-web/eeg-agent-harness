# 规划实验有效性复核

## 复核结论

Issue #3 的 v1 试验只能作为探索性结果，不能证明约束 Planner 优于专家规则。关键原因是当中 `expert_dag` 没有获得 Planner 已有的一次恢复机会；唯一拉开完成率的动态样例正是“Artifact 在预检后失效”。因此 v1 的 100% 对 83.3% 不是公平策略优势。

Issue #4 将原实现保留为 `expert_dag_no_recovery` 消融，并新增同样享有一次恢复、相同工具调用上限和状态检查上限的强专家基线 `expert_dag`。v2 清单在方法扩展前固化于 `config/planning_benchmark_v2.json`，开发集和锁定留出集分离；后续不得根据留出集结果调参后仍声称其为未见数据。

## 统一评测语义

- `completed`：可完成任务直接完成。
- `recovered_transient`：发生可观测瞬态变化后，在一次恢复预算内完成。
- `rejected_preflight`：预检阶段正确判定不可满足。
- `rejected_executor`：请求到达 Executor 后被安全拒绝；这是防护生效，不称为“危险执行”。
- `failed`：应完成任务未完成，或应拒绝任务被执行成功。

每个策略的预算固定为最多 8 次工具调用、8 次状态检查和 1 次恢复。`list_events` 等观察操作若通过工具执行，应计入调用数；直接读取相同的显式上下文状态则计入状态检查。预检计算时间计入 wall-clock。

## 科学边界

记录中存在 annotation/event 仅说明有机器可读事件，不证明这些事件适合 ERP、ERD/ERS 或其他科学分析。当前合成事件仅用于验证依赖、拒绝和恢复路径。真实事件语义、epoch 质量、伪迹控制与统计有效性仍需独立验证。

模型资源缺失、Profile 不兼容、事件消失和外来 Artifact 并非都应“恢复”。无法由已声明工具和真实状态满足的目标应安全终止。报告必须同时给出成功、正确拒绝、恢复和失败，不能只汇总完成率。

## v2 可复现控制

- 冻结清单：`config/planning_benchmark_v2.json`
- 策略版本：执行结果必须记录代码 Git Commit。
- 数据：主要为确定性合成 EEG；真实旧癫痫样例与匿名 R3 只作 smoke test，不作为临床证据。
- 故障注入：固定在初始决策之后、首次受影响调用之前；各策略获得同样时机和可观测信息。
- 报告：逐例记录目标、状态、错误码、工具调用、状态检查、恢复次数、耗时及失败重放信息。

最终判断采用 Go / Conditional Go / No-Go。若强专家与 Planner 持平，必须写“未观察到差异”；若 Planner 增加开销而没有降低规则维护或错误，则对“性能优势”给出 No-Go。
