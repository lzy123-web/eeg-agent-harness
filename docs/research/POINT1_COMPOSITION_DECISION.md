# Issue #34 一页研究判断：组合泛化是否形成工作点一？

**结论：暂不提出新 Planner；对“未预置任务的科学合法组合规划算法”作有界 NO-GO / PIVOT 讨论。**这不否认多任务 Harness 的工程价值，而是否认本轮已有证据足以支持新的独立规划算法主张。保留 PR #27 的 v3 与全部历史负结果，不启动 Issue #34 阶段 C。

## 究竟检验了什么

冻结 10 条连续、事件、模型及跨族组合请求，其中 4 条作为首次真实模型 holdout；要求按目标参数/作用域、Profile、资源、事件边界和证据来源交付，不按唯一工具序列评分。v3 在真实 DeepSeek（请求 `deepseek-chat`、响应 `deepseek-flash`）的开发集为 5/6 预定结局、holdout 4/4；唯一开发失败 D02 是模型拼接了非连续 `request_quote`，Harness 安全误拒。H01 涉两事件 scope 和连续窗的依赖组合已通过，H04 在末端越界后停机。现有真实观察**没有反复出现“目标正确、工具能力存在，但共同核心不能合法合成依赖计划”**。因此不符合 Issue #34 阶段 C 的启动门槛。

## 相对已有工作有什么实际增量

当前系统实际具备：同一 EEG Record/Profile/Registry/Executor 上的多目标实例、确定性前提检查、事件 artifact 来源绑定、结构化停止和逐目标证据包。这些是有价值的可运行 EEG Harness 能力，但 [EEGAgent](https://ojs.aaai.org/index.php/AAAI/article/download/38867/42829) 已做 LLM EEG 工具规划，[CogEEGAgent](https://arxiv.org/abs/2607.25045) 已做 typed 科学授权，[WINGS](https://www.wings-workflows.org/) 已做语义约束工作流生成，[ReAct](https://arxiv.org/abs/2210.03629) 已做反馈行动；“LLM 提目标 + typed graph + Executor”不能仅改名即称原创。原生 Agent 在 H01 用合并 producer 完成相同科学目标，仅 3 工具调用，v3/当前 Expert 各 6；这进一步反对当前方法的效率优势叙事。D02 的误拒与 D05/D02 原生回答错误分别是意图引文合同与回答证据工程问题，不是足以支撑新 Planner 的共性机制发现。

## 是否值得继续

**KEEP** 多任务 EEG Harness 作为论文系统基础；**STOP** 为本轮数据另造 planner、追加事件规则或用固定脚本作弱对手。工作点一若仍主张“未预置任务泛化的独立方法”，现有证据不足，应与导师讨论 **PIVOT** 到有明确反事实和公允最近邻的研究问题，或收缩为工程集成/科学可靠性系统贡献。未来只有在先验冻结的、更广泛 EEG 科学能力与用户请求上，反复发现正确目标下的跨任务计划缺陷，并证明同合同 Strong Expert、typed workflow、Plan-and-Execute 难以同等解决或人工适配成本显著不同，才可重新进入方法研发。不可把本轮有限合成 9/10、一次 Native 回答错误或不同比例的工具调用自动当作学位论文创新证据。

## 下一项最小决定性证据（需另立协议，不在本轮偷跑）

选定一项**现有注册但 v3 未迁入**且具有独立科学状态影响的合法操作，先为所有方法提供同一 ToolSpec/授权/Profile/输入输出科学合同；冻结至少两种与连续、事件、模型目标的未见依赖组合及同预算扰动。预注册每臂的合同编写/维护工作量、合法完成/误发布、执行调用与证据来源，再运行真实模型。若 typed-workflow/强 Expert 以相同合同达到同等科学正确性且维护量不高，则仍为系统能力而非原创算法。此建议不是本轮实施许可；须先核查科学适用性、数据资源与伦理边界，且不能修改旧冻结方法/结果。
