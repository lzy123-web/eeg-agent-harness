# 工作点一 CCEP 方法决策

日期：2026-10-23。

## 决策

**当前 CCEP v0 对“相对强基线产生额外性能价值”的主张判定为 No-Go；对“作为可审计的科学执行安全骨架继续保留”判定为 Conditional Keep。**

这不是否定“EEG 状态感知与约束规划”研究问题，而是拒绝把尚未产生可测增益的实现包装成已成立创新。

## 依据

1. 实现贡献真实存在：同一 obligation 跨越自然语言意图、计划、派生 artifact、有限恢复和最终证据发布；筛选授权、质量前置、artifact lineage 与回答数值均可 fail-closed 检查。这超出单个 Prompt 的临时提醒。
2. 但当前冻结实验无法证明增量作用：18 个共享任务上 CCEP 与同规则强 route+preflight 都是 18/18 正确、10/10 科学完成，工具调用与重规划完全相同。
3. 两个真实 DeepSeek holdout 中 Native 2/2，CCEP 1/2。CCEP 的失败是安全误拒，不是科学误执行，但仍降低任务完成率。
4. 原子目标组合解决了既有“禁止筛选仍需质量+功率”的表达缺口；这是合理能力修复，不能单独当作研究创新证据。
5. 独立 oracle 证明筛选链数值正确，但只回答 implementation correctness，不回答 method superiority。

## 可以与不可以声称的内容

可以声称：

- CCEP v0 已真实接入现有 Agent/Planner/Executor；
- 它能在受控合成任务中保持筛选授权、状态 lineage 和回答证据一致；
- 它在失败时能阻止无证据的后续执行或回答发布。

不可以声称：

- CCEP 优于原生 Agent或同规则强专家；
- ledger 已被证明是性能提升来源；
- 合成质量筛选具有临床效度；
- 两个真实 LLM 案例代表泛化性能。

## 若继续工作点一的严格入口

下一轮不应继续堆叠流程或围绕本次 holdout 调 Prompt。只有满足以下条件才重新进入方法比较：

1. 预先提出至少一种强 preflight 无法等价表达、但持续 obligation/状态变更理论上可区分的失败模式；
2. 在方法修改前冻结新任务、独立标注、Native/Strong/CCEP 权限和统计计划；
3. 把意图解析、规划、执行恢复、回答忠实度分层计分；
4. 使用多个措辞重复和至少一个真实但可本地离线处理的事件数据来源；
5. 若 ledger 消融仍与完整 CCEP 持平，则将其降级为工程安全机制，并重新论证论文工作点而不是继续增加 validator。

当前最精确的继续入口是：先研究“执行中状态变化或恢复是否会使一次性 preflight 失效”，而不是继续扩大静态任务数量。
