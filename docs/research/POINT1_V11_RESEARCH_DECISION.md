# CCEP/LRSP v1.1 研究判断

更新时间：2026-10-23（Asia/Shanghai）

## 结论

当前判断为 **Conditional Keep / 尚未进入正式公平实验**。

CIEDG 已解决一个真实架构问题：动态科学状态不再只服务固定 bandpower 流程；多个目标通过可审计依赖图共享 effective Epoch，完成证据会随内容 lineage 和上游语义自动失效，内容等价重建时可有限恢复。它是运行时算法，不是单纯 Prompt、Schema 或 Validator。

但小型公平诊断中，同规则过程式强 Expert 用相同 6 次工具调用得到完全相同的科学输出。当前没有成功率、成本或科学正确性优势证据，不能宣称优于强 Expert，也不能据此宣称论文创新已成立。

## 可能构成论文贡献的机制

以下组合值得进入正式假设检验，但贡献性仍待对照和消融证明：

1. **科学目标—证据—artifact 三层绑定**：完成不是布尔标志，而是绑定任务参数、输入内容版本、上游证据和状态模式的 token。
2. **EEG 状态驱动的 residual frontier**：质量、每条件 usable count 与用户授权共同决定 identity/derived/stop，而非由 LLM 猜测下一工具。
3. **依赖传播与内容等价局部恢复**：状态变化只撤销受影响目标；纯 consumer 在科学语义等价时可复用，内容改变时必须重算。
4. **自然语言 obligation 到运行证据闭环**：请求目标、实际分支与最终回答引用在同一执行中闭合。

这些机制的论文价值应落在“动态 EEG 状态下科学承诺如何保持有效”，不是泛化地声称提出了新 DAG 或 provenance。

## 仅属工程优化的部分

- `point1-v11` CLI 开关、JSON 序列化和结构化错误码；
- fingerprint 周期内缓存与测试夹具；
- 新增 `epoch_summary` 工具目标本身；
- Fake LLM、多标签关键词解析；
- 把目标元数据放入 Python contract 表。

单独使用上述工程项不能作为论文创新。

## 失败与负结果

- 迭代 0 能修复丢失 artifact，但重复执行已完成 summary；说明依赖失效正确不等于最小恢复。
- 迭代 1 解决内容等价重建的重复 consumer；源内容改变时仍必须重算，不能追求更少调用而牺牲有效性。
- 多条件中一个条件零 usable 会终止整个请求；当前没有用户授权的降级目标或“只分析剩余条件”语义，不能自动删条件。
- 独立运行 fingerprint 不相等并非数值不一致，而是 evidence ID 含随机 artifact ID；这暴露 provenance identity 与 scientific equivalence 尚未彻底分层。
- CIEDG 与强 Expert 无故障诊断完全持平；没有观察到结果优势。

## 进入正式实验前的门槛

目前不建议立刻开展大规模比较。需先完成：

1. 冻结覆盖状态改变、部分完成、内容等价/不等价、授权冲突和多条件空集的独立任务集；
2. 实现同信息、同科学规则、同工具、同恢复预算的强动态 Expert，不能只比较静态 DAG；
3. 冻结主要指标：科学完成、非法操作、陈旧证据发布、无关重放、工具/LLM 成本和恢复范围；
4. 把语言解析错误、规划错误、工具失败和回答歪曲分层统计；
5. 增加至少一个不同状态转移族，而非只增加另一个只读 consumer；候选可为明确授权的重参考/重采样后证据失效，但必须先验证科学合法性；
6. 修正或显式规范化跨运行 scientific equivalence，避免随机 provenance ID 污染公平比较。

满足门槛后再预注册开发/holdout 与消融：去掉 semantic token、去掉 content cache、退化为布尔完成、退化为全量重规划。若强 Expert 在正确性和成本上持续持平，则论文叙事应收缩为可审计执行框架设计，而非性能优越方法。
